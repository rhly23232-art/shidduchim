# תפעול ותמיכה — שידוכים

## 1. רישום שגיאות (לקוח)

`src/lib/log.ts`:

- כל שגיאה לא צפויה עוברת דרך `logError` ומסווגת לאחת מהקטגוריות:
  - `user`: המשתמש יכול לתקן (אימות, התנגשות, סיסמה שגויה, הגבלת קצב).
  - `recoverable`: שגיאה זמנית.
  - `provider`: שירות חיצוני נכשל (מייל, Gmail, אחסון).
  - `data`: בדיקת עקביות עצרה פעולה (שום דבר לא שונה).
  - `system`: באג.
- מידע אישי (מיילים, טלפונים, טוקנים) מוסר לפני כל רישום.
- 200 הרשומות האחרונות נשמרות בזיכרון, ושגיאות גלובליות (`error`, ‏`unhandledrejection`) נלכדות.
- אם `VITE_ERROR_ENDPOINT` מוגדר, שגיאות נשלחות אליו כ-JSON. בלעדיו, הרישום מקומי בלבד.

## 2. דוח תמיכה

תפריט משתמש ← "תמיכה ועזרה" ← "הורדת דוח תקלות" מוריד קובץ JSON שכולל:

- גרסה (`package.json` + git sha, מוצגת גם בתפריט), סוג backend ודפדפן.
- בדיקות חיות: סשן, קריאה מהמסד, יומן, ובמצב Supabase גם תקינות פונקציית המייל.
- השגיאות האחרונות, לאחר הסרת מידע אישי.

הדוח לא כולל נתוני מועמדים. בפנייה לתמיכה יש לבקש את הקובץ הזה.

## 3. Edge Function

- הלוגים זמינים בלוח הבקרה של Supabase ← Edge Functions ← Logs, בשורות JSON עם `ts`, ‏`level`, ‏`event` ושדות לפי האירוע (`user`, ‏`status`, ‏`attempt` וכו'; ללא כתובות נמענים).
- בדיקת תקינות: GET לפונקציה מחזיר `configured` כשהסודות מוגדרים.
- כל שליחה נרשמת ב-`email_log` (סטטוס, זמנים, מפתח idempotency). מכאן מחושבת הגבלת הקצב.
- תקלות נפוצות:
  - 429 מהאפליקציה: המשתמש חרג ממכסת השליחה.
  - `configured:false`: חסר `RESEND_API_KEY` או `RESEND_FROM`.
  - 502 / timeout: Resend לא זמין. נעשה ניסיון חוזר אחד, ושליחה חוזרת מהממשק בטוחה (idempotency).

## 4. נתונים

- **גיבוי למשתמש:** עמוד "גיבוי ושחזור" יוצר ZIP מלא, עם תזכורת שבועית.
- **גיבוי מסד:** הגיבויים של Supabase (תלוי בתוכנית). מומלץ PITR בייצור.
- **סל מחזור:** מחיקות נשמרות 30 יום ביומן.
- **מחיקת נתונים / חשבון:** עמוד "החשבון שלי" (`/account`, קישור מחלון "תמיכה ועזרה"). דורש הקלדת "מחיקה" וסיסמה. מחיקת חשבון מוחקת את המשתמש מ-`auth.users`, ובשרשור את כל השורות. קבצים ב-Storage נמחקים לפני כן.

## 5. ניטור מומלץ

- הגדרת `VITE_ERROR_ENDPOINT` לשירות איסוף שגיאות.
- התראות מ-Supabase על שימוש במסד ובאחסון.
- מעקב אחרי שיעור `failed` ב-`email_log`.
